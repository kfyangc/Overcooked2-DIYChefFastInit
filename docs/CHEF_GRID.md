# 厨师网格选择（2.2.0.9 测试版）

主菜单打开“厨师”时默认显示 10 列 × 5 行的分页网格，行数和列数可配置。左侧使用零间距、无名称及玩家编号的连续方格，以粗彩色边框标记选择；右侧保留名称和独立高清头像。厨师图像使用透明背景。条目数随实际可选厨师变化，移动到其他页会自动翻页。新增功能的生产代码全部放在 `ChefGrid/`，离线回归放在 `tests/ChefGrid/`。

根据用户的 `preview_2.2.0.1.png` 反馈，2.2.0.2 改为独立顶层 Canvas，消除原菜单继承缩放；所有文字及操作区纳入同一个不透明面板，背后增加全屏遮罩。卡片改为独立的方形图片和两行名称区域，字体换为清晰的系统字体。右侧头像从单独的 512 × 512 渲染或缓存读取，不再放大网格缩略图。模型按完整边界留白，取消底部裁切。

根据 `preview_2.2.0.2.png` 和 `TableOfChef.jpg`，2.2.0.3 将左侧改为头肩特写：按选中头部及 Head1/Head2 的实际蒙皮后顶点计算边界，帽子、尾巴和身体不参与缩略图缩放。右侧保留完整模型，以头部的横向中心对齐，适应尾巴等不对称部件。只在离屏副本上使用 BakeMesh 并更新其局部边界，不修改玩家模型；临时网格在菜单关闭时释放。

`preview_2.2.0.3.png` 显示近景中多数头部缺失。2.2.0.4 撤销直接改写 SkinnedMeshRenderer.localBounds 的路径：每次拍摄将可见蒙皮部分 Bake 为临时 MeshRenderer，构图与渲染使用同一份顶点，拍摄结束后恢复原渲染器并释放临时对象。Unity 2017.4 的蒙皮边界与离屏更新机制见 [localBounds 官方说明](https://docs.unity.cn/2017.4/Documentation/ScriptReference/SkinnedMeshRenderer-localBounds.html)。

左侧移除名称后增加为四行，右侧保留名称。图像经过黑/白背景两次渲染恢复透明 Alpha，可兼容只输出 RGB 的游戏 UI 着色器，并保留黑色衣物与半透明边缘。新版缓存使用新的构图版本，旧蓝底或缺头缓存不会继续使用。

2.2.0.5 根据 `preview_2.2.0.4.png` 调整三处行为。拍照前重新绑定并定格动画，恢复预制体的睁眼骨骼变换、关闭 `Eyes2_Blinks` 部件，避免截取眨眼瞬间；动画重新绑定接口见 [Unity 2017.4 Rebind](https://docs.unity3d.com/kr/2017.4/ScriptReference/Animator.Rebind.html)。青色双马尾厨师为 `69-MikuFufu`，其 Head OBJ 宽约 1.615、Eyes 宽约 0.335；头发明显扩大了头部轮廓，因此对头部轮廓与眼宽比例过大的角色改按眼睛定位和缩放，普通比例保持既有构图。新增网格行列配置，绘制、点击命中和翻页共用同一个布局对象。

`preview_2.2.0.5.png` 仍有厨师缺眼。2.2.0.6 参考同工作区 `Overcooked-2-MOD-Manager/src-tauri/src/diychef/preview/native/mesh.rs`、`native/visibility.rs` 和 `custom.rs` 的实现：原版头部可能把睁眼、眉毛和闭眼层合并在一个蒙皮网格中，不能仅按渲染器名称隐藏。拍照副本禁用 Animator 后，从实际厨师预制体恢复完整子层级的局部变换和混合形状权重，不再调用 Rebind/Update 或把闭眼骨骼缩为零。独立 Eyes 部件同时恢复对象激活和渲染器启用状态；合并网格根据四个骨骼权重识别 Eyes2_Blinks 顶点，剔除相关三角形并压紧顶点/法线/UV/颜色等属性，避免闭眼顶点干扰构图。以上操作只作用于离屏副本及临时快照网格，保留共享预制体和玩家模型。

`preview_2.2.0.6-1.png` / `-2.png` 显示部分头像仍像全身照，戴眼罩的松鼠和乌龟又被放大到单眼。2.2.0.7 将蒙皮顶点的头部、眼睛、闭眼标记随快照压紧映射一起保留，能从合并的原版网格提取眼睛与主要受头部骨骼影响的顶点。含全身的刚性 Head.obj 无法仅靠权重区分身体，因此取景时排除颈部平面下方的顶点；颈部与眼骨骼的距离作为缩略图尺寸标尺，防止龙的胡须、长耳朵或额外装饰把脸缩得过小。只有跨过脸部中线的成对眼睛才能触发眼宽缩放；单眼角色沿用整张脸的范围并按骨骼中线居中，保留原有眼罩。右侧完整模型不受缩略图尺寸上限影响。上述分类与裁切只用于相机取景，不改模型的实际骨骼绑定。

`preview_2.2.0.7.png` 中的原版 `Chef_Crocodile` 眼睛间距窄且位于头顶，误触长发角色的放大规则，导致嘴部被裁掉。2.2.0.8 增加相对头部高度判断：眼睛中心位于头部上方四分之一范围时，保留常规头部取景，不以眼宽放大。该规则根据几何特征判断，没有厨师名称特判。鳄鱼的正交相机半宽由约 0.312 恢复为 0.496，纵向中心从约 1.234 回到 0.899，容纳长嘴和下颚。

2.2.0.9 调整呈现：方格按统一边长紧邻排列，整块网格在可用区域中居中，不再把剩余宽高分摊为格间空白。普通边线为 1 个设计像素，选中边框加粗至最多 6 像素，并覆盖在图像上，选择时不会缩放头像。移除头像上的 P1–P4 文字，顶部玩家标签继续用于切换鼠标操作的玩家；多人同选一格时，各边以玩家颜色区分。右侧取消裁剪缩略图回退，高清预览未就绪时显示加载提示，就绪后用 0.15 秒淡入；加载失败时显示相应提示。本次沿用 2.2.0.8 的头像构图和缓存。

**本轮未启动游戏。** 已通过目标游戏程序集的 net35 编译，以及 .NET 11 和游戏自带 x86 Mono 的布局/逻辑回归；零间距边界点击、加粗边框和淡入的实际呈现仍需游戏内复测。

## 原版能力调研

直接反编译本机游戏的 `Overcooked2_Data/Managed/Assembly-CSharp.dll`，没有启动游戏。调研时该文件 SHA-256 为 `9bb6a3791331201d32ca89c3509f019a9780309da7110002f04020e8491e1908`。同目录已有的 `Assembly-CSharp.dll.测1菜单` 备份，其 `FrontendChefMenu` 反编译结果与当前文件一致。结论限定于这套本机程序集，未比较其他平台和游戏版本。

| 类型 / 方法 | 已有能力 | 对实现的影响 |
| --- | --- | --- |
| `FrontendChefMenu.Show/Hide/Close` | 打开、确认、取消、镜头切换与菜单生命周期 | 沿用原菜单；确认调用 `Hide`，取消调用 `Close` |
| `ChefCustomiser.CacheCurrentAvatars/RevertAvatars` | 按输入槽位和分屏状态缓存、恢复官方头像 | 继续使用已有 DIY 快照补丁恢复额外厨师 |
| `FrontendChefCustomisation.Update/SetChefSelection` | 每位玩家的左右输入、循环选择、发送官方头像 | 没有多行厨师列表或多头像预览；网格打开时替换这部分输入处理 |
| `T17NavigableGrid` | 动态添加条目、二维导航 | 是通用 UI 基类，依赖边缘 Selectable、T17EventSystem，并只维护一组当前选中索引 |
| `T17ScrollView` | 基于上述控件滚动到条目 | 可以用于单光标列表；仍需自行提供厨师条目、头像和多玩家状态 |
| `ChefAvatarData` | 前端、关卡和 UI 三套 3D 预制体 | 没有头像纹理字段，不能直接填充二维头像网格 |
| `PlayerInputLookup.GetFixedButton/GetFixedValue` | 按 PlayerGameInput / PadSide 映射逻辑输入 | 复用设备映射；纵向用 MovementY，避免通用 UIUp/UIDown 为分屏键盘额外注入共享方向键 |

因此原版没有可直接启用的完整厨师表格。实现使用游戏已有的 Unity uGUI 组件构建独立覆盖层，自行管理分页和各本地玩家光标，同时复用原版模型、设备映射、菜单生命周期及原有 Mod 的加载/通信路径。没有修改游戏 DLL，也不需要额外 AssetBundle。

## 操作与扩展

- 手柄十字键 / 摇杆，或各玩家映射的移动键：上下左右移动，可长按连移。
- 方向键：控制当前活动的键盘玩家；点击上方 P1–P4 标签切换鼠标操作的玩家。
- 滚轮、PgUp / PgDn 或底部分页按钮：翻页查看，不立即改变选择。
- 点击头像：为活动玩家选择厨师。多个本地玩家可分别移动光标，以玩家颜色的粗边框区分选择；头像上不再覆盖 P 编号。
- 原版确认键、空格 / Enter、确认按钮：保留选择并退出；原版取消键、Esc、返回按钮：恢复进入菜单时的选择。

启用 `prefer.txt` 时沿用登记、过滤后的顺序，只显示可用的官方厨师和已登记的额外厨师；没有启用偏好列表时显示已解锁的官方厨师。新厨师沿用现有资源目录、INFO 和 ID 规则登记后会自动增加页数，无需修改网格代码。额外厨师 ID 仍使用现有协议的 0–254。

选择时先安装额外 ID，再发送官方头像及额外 ID，最后刷新显示。额外厨师的官方替代外观沿用已有默认值，允许纯额外厨师列表。远端玩家不接受本地光标操作。玩家加入、离开或重排后，以输入槽位和分屏身份保留本地光标。

## 头像与配置

冷缓存时，右侧先显示当前厨师名称，然后逐个补齐当前页头像。单独的离屏渲染对象沿用 `ChefLoading` 的异步读取和主线程预算，一次只准备一位厨师；实际玩家预览有待加载任务时，头像生成让出加载器。离屏对象不触发 ModelTest 粒子补挂。

左侧缩略图使用 128 × 128 头肩特写 PNG，右侧独立使用 512 × 512 完整模型 PNG，均为 RGBA，放在 `BepInEx/cache/DIYChefFastInit/portraits/`；高清缓存使用 `.512.png` 后缀，下次打开或重启直接读取。缩略图缓存目标为 96 张或当前需要显示的数量中的较大值，避免高密度页面反复回收仍需显示的图片；此外保留一张当前高清图、两个渲染目标和一个离屏模型，关闭菜单或卸载插件时释放。静态快照网格与透明度计算的白底临时纹理在每次拍摄后释放。切换厨师时优先准备高清图，期间右侧显示加载提示，保持图像来源与构图一致。缓存键包含构图版本、厨师、帽子、颜色、朝向、程序集时间/大小和额外资源文件的路径、大小、修改时间；2.2.0.9 沿用 2.2.0.8 的缓存键，不需要清理或重新生成已有头像。该视觉缓存不做资源内容校验；同大小同时间戳替换素材后，可删除 portraits 目录重建，实际模型资源缓存仍使用原有完整校验。

额外厨师目录可提供 `preview.png`，优先作为头像。建议使用正方形、512 像素的图片；列表将其降采样为 128 像素。较小的图片仅用于列表，右侧仍自动渲染高清模型。可用此方式为不适合统一构图的厨师指定头像。

配置文件 `dev.gua.overcooked.diychef.cfg`：

```ini
[ChefSelection]
GridEnabled = true
GridColumns = 10
GridRows = 5
PortraitYaw = 0
```

`GridColumns` 范围为 4–16，`GridRows` 范围为 2–8；每页数量为二者乘积，格子自动缩放、保持正方形并以零间距连续排列，多出的空间留在整块网格外侧。配置管理器中修改后重开厨师菜单生效；直接编辑配置文件时退出游戏、保存后重新启动。`GridEnabled=false` 使用原左右轮播；`PortraitYaw` 调整生成头像的模型旋转角度，修改后自动使用新的缓存键。界面或头像初始化异常会记录日志；界面异常回到原菜单，单个头像失败时仍可移动光标并查看右侧名称。

2.2.0.9 扩展现有布局回归，覆盖全部 91 种允许的行列组合，验证上下/左右相邻方格零间距、共享边界两侧的点击归属、外侧留白、首末角点和部分填充页。绘制与命中共用预先存储的单精度边界，避免游戏 x86 Mono 在重复浮点计算时与绘制位置产生差异；居中留白限制为非负值。常规 350,382 项断言在 .NET 11 和游戏自带 x86 Mono 下均通过。新增边框与大图淡入只做目标程序集编译和代码检查，实际 uGUI 画面不在离线回归范围内。
