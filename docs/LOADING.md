## 构建与安装

安装 .NET SDK，然后执行：

```powershell
./tools/Fetch-Lz4.ps1
dotnet build -c Release "-p:GameDir=D:/Games/Steam Games/steamapps/common/Overcooked! 2"
```

也可以设置 OC2_GAME_DIR 环境变量。依赖直接取自目标游戏的 Managed 和 BepInEx/core，保持 net35 兼容，不把游戏程序集复制到产物中。输出为 bin/Release/DIYChefFastInit.dll，当前版本为 2.2.0.15。测试版版本号迭代用第四位。

Fetch-Lz4.ps1 获取并校验固定版本的官方 x86 LZ4 库，缓存在忽略提交的 lib 目录。构建将它及许可证嵌入插件 DLL；安装只需 DIYChefFastInit.dll。首次使用时自动释放到 BepInEx/cache/DIYChefFastInit/native。第三方声明见 THIRD_PARTY_NOTICES.md。

退出游戏，将安装目录中旧的 OC2DIYChef.dll 或 DIYChefFastInit.dll 备份到 plugins 目录之外，再将新的 DIYChefFastInit.dll 放到原插件目录，保留旁边的 Resources 和 prefer.txt。避免在 plugins 下留下第二个同 GUID 的插件。插件 GUID 和配置文件名保持不变，可沿用现有资源、配置及磁盘缓存。重启后，在 BepInEx/LogOutput.log 核对 Loading 行的版本及 Version 行的完整 DLL 路径。

## 行为与配置

成功读档后登记 INFO、BODY、选择顺序、帽子和资源路径，不在启动阶段导入厨师贴图、OBJ 或三种模型。重复读档不重复登记或订阅事件。

前端选择使用单个后台读取/解析任务；主线程以约 3 ms 调度预算分步解码、上传和构建，旧模型继续显示。每个显示对象只保留最新选择。纹理解码/上传等单次 Unity API 调用不能被预算抢占，仍可能形成长帧。InGame 创建链保留同步兼容入口，其等待时间单独写日志。

每个型号、渲染器持有独立绑定网格，纹理跨型号共享。缓存资源由实际实例引用保护；关闭或销毁显示对象后取消不再需要的工作。实例销毁时回收其材质副本。

登记实例材质时，通过 Renderer.materials 取得当前渲染器独立的材质，再纳入销毁清单，不以名称中的 (Instance) 推断所有权。这样外部插件挂载的粒子也使用独立副本，销毁餐车厨师时保留 ModelTest 的共享预制体材质和其他厨师的材质。

BepInEx 配置文件 dev.gua.overcooked.diychef.cfg：

| [Loading] 项目 | x86 默认 | x64 默认 |
| --- | ---: | ---: |
| CacheBudgetMiB | 64 | 128 |
| MaxCachedChefs | 3 | 6 |
| Diagnostics | false | false |

既有配置值保留。超过任一缓存目标时按最近使用情况回收闲置资源；正在加载、等待应用和被实例引用的资源暂时保留。估算预算不等于整个游戏的内存上限。

Diagnostics=true 时记录资源准备、纹理解码上传、应用、首个相机绘制帧、帧 P95/最大值、Windows Private Bytes/Working Set、缓存估算和引用情况。相机绘制回调表示相机完成该帧绘制，不代表显示器扫描输出或 GPU 硬件计时。

## ModelTest 粒子兼容

安装插件 ID 包含 modeltest 字符串的 ModelTest 时（忽略大小写，不限制前缀和后缀），FastInit 在实际厨师实例更换后的下一帧调用其粒子挂载方法。检测到插件后仍检查字段和方法签名。同一帧的更换请求合并执行；资源尚未加载完时保留请求，等待就绪后执行。首次加载和内存缓存命中的切换共用此路径，覆盖前端、关卡和 UI 型号。没有更换实例时不会持续扫描场景。

兼容层只读取 ModelTest 的 resourcesLoaded、particleReplacer 字段，并调用无参数、返回 void 的 Execute 方法，不调用模型替换、不修改 ModelTest DLL。ModelTest 的配置仍按名称、父节点和祖父节点匹配，自定义厨师节点名包含 Chef_ 前缀。

日志中的 ModelTest particle compatibility enabled 表示接口检测通过，并附上实际匹配的插件 ID。若内部接口改变或调用异常，会记录一次 ModelTest particle compatibility disabled 并停用补挂，厨师加载继续运行。未安装 ModelTest 时保持静默。

离线回归命令（不加载 Unity、不启动游戏）：

```powershell
dotnet run --project tests/ModelTestCompatibilityRegression.csproj -c Release
```

回归覆盖可选插件缺席、资源延迟就绪、同帧合并、同实例不重复触发、切回后重新触发、接口变化、调用异常与关闭清理。实际特效显示仍需在游戏中验证。

## 1.3.0.4 持久化资源缓存

在 BepInEx/cache/DIYChefFastInit 保存解析后的 OBJ 几何和解码后的纹理像素、原始格式及 mipmap。内存中已有模型仍直接复用；资源被内存缓存回收或游戏重新启动后，可从磁盘缓存恢复，跳过 OBJ 文本解析和 PNG 解码，仍需创建 Unity 对象并上传 GPU。

新增 [Loading] DiskCacheEnabled，默认 true。原有 CacheBudgetMiB、MaxCachedChefs 保留用户配置，不因磁盘缓存而增加。解码贴图每次最多保留一个后台写入缓冲区，并纳入临时内存诊断。

原文件使用 SHA-256 内容指纹，缓存使用结构版本及负载校验和；原资源在下次导入时变化、缓存损坏或结构不兼容时，回读原资源并重建。缓存写入失败不阻止原资源加载。删除该缓存目录会让后续使用重新生成缓存，不影响厨师 ID、选择和资源原文件。

离线验证与 OBJ 预生成命令：

```powershell
dotnet run --project tests/DiskCacheRegression.csproj -c Release
dotnet run --project tests/DiskCacheRegression.csproj -c Release -- --warm "<插件 Resources 目录>" "<游戏目录>/BepInEx/cache/DIYChefFastInit"
```

回归覆盖内容变化（包含大小和时间戳均不变）、命中、损坏、截断、结构版本、空 OBJ、纹理格式/mipmap、取消、禁用缓存和写入失败。离线预生成只处理 OBJ，不启动游戏；PNG 像素由游戏首次使用时按原加载方式生成缓存。完整切换耗时及纹理缓存的实际渲染表现仍需游戏内确认。

本机离线检查：19 项缓存断言通过；已在指定目录预生成 349 个 OBJ 缓存，并逐项验证再次读取后的顶点、法线、UV、三角形一致。独立工具的磁盘再读合计约 0.91 秒，此数值不代表游戏切换耗时。

## 1.3.0.5 校验与重复扫描优化

缓存读取使用 Windows 原生 SHA-256，并对刚读出的像素或几何字节进行校验，不再先扫描整个负载、回到起点后再读取。纹理直接校验最终的像素数组；网格一次读入当前文件的紧凑字节缓冲区，验证后从内存恢复。写入采用 64 KiB 缓冲，同步生成摘要，避免写完后再次读取整个负载。

缓存结构版本保持 1，原有 .mesh/.texture 文件直接兼容。源文件仍进行完整内容指纹检查，负载仍进行完整 SHA-256 验证；同尺寸、同时间戳的源内容变化也会失效。Windows 原生实现不可用时回退托管实现，并记录日志。启动日志会显示实际使用的校验后端。

游戏自带 x86 Mono 的离线探针（同一套 Anya 缓存，每项预热后测 5 次，取中位数）：

| 阶段 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 贴图缓存读取与校验 | 331.56 ms | 32.36 ms |
| 全部网格缓存读取与恢复 | 98.25 ms | 52.90 ms |
| 主要贴图与网格导入循环 | 442.53 ms | 86.32 ms |

28 项缓存/摘要回归通过，349 个原有 OBJ 缓存全部命中并通过数据往返检查，不需要重建缓存。Release/net35 构建为 0 警告、0 错误。本轮没有启动游戏；这些是 CPU 数据导入探针结果，完整模型构建、GPU 提交和首个显示帧仍需实际游戏复测。

## 1.3.0.6 网格恢复与分段定位

磁盘缓存经原有完整校验后，直接恢复已读出的浮点几何，批量复制索引，避免在旧 Mono 中逐个标量经过 BinaryReader、FillBuffer 和 MemoryStream。尺寸、索引边界和取消检查保留，缓存格式不变；同一个资源目录只枚举一次。

游戏自带 x86 Mono 的同进程对照中，Anya 全部网格的纯数据恢复从 25.28 ms 降到 0.69 ms，结果逐项一致。33 项缓存/摘要/恢复回归通过，349 个 OBJ 与缓存结果逐字节一致。Release 构建 0 警告、0 错误。

实际游戏的 1.3.0.5 日志仍有约 300–350 ms 后台等待，不能用离线加速数字宣称已全部修复。新增正式后台分段、线程 CPU/GC 计数和主线程准备累计计时，用于下一次用户游戏测试继续定位。详细阶段含义与证据见 CHEF_SWITCH_PERFORMANCE.md。本轮没有启动游戏，实际切换速度尚待测试。

## 1.3.0.7 校验上下文与原生像素缓冲

1.3.0.6 用户测试日志中，命中导入的后台时长中位数仍为 275.80 ms，网格恢复已降到 0.86 ms。继续移除每次摘要都初始化 Windows 服务的重复工作：同一后台导入复用一个服务上下文，各摘要使用独立句柄；Anya 的上下文创建次数由 24 次降到 1 次。缓存文件名仍用相同 SHA-256 字节，短路径摘要不再初始化原生服务。

缓存像素经 64 KiB 传输缓冲读入短期原生内存，通过 Unity 的指针接口载入，Apply 后释放，避免命中时分配整张约 22 MB 的托管数组。PNG 命中时只流式计算指纹，未命中时保留原来的 LoadImage 路径。缓存结构、完整内容校验、像素格式、mipmap、画质和驻留预算不变。取消、失败和未消费结果都会释放原生暂存，并记录 nativePixelBytes。

61 项回归通过，覆盖并行摘要隔离、作用域生命周期、实际导入、指针数据一致性与失败释放；349 个 OBJ 缓存逐字节核对通过。游戏自带 Mono 中 128 个短摘要由逐次创建上下文的 39.23 ms 降到复用的 0.76 ms；此数值只描述该项开销。正式 Worker 离线三次为 95.38、66.16、68.68 ms，完整游戏效果待用户复测，本轮未启动游戏。详细证据及计时限制见 CHEF_SWITCH_PERFORMANCE.md。

## 1.3.0.8 LZ4HC 纹理缓存

纹理缓存使用 LZ4HC level 9 压缩、原生 LZ4 解压。像素、ARGB/RGBA 格式及全部 mipmap 不变，仍完整校验解压后的像素和元数据 SHA-256，保持同尺寸同时间戳源修改的失效检测。网格缓存格式保持 1；纹理兼容格式 1，压缩完成后为格式 2。

启动后单个低优先级后台任务逐份转换已有原始缓存。新 PNG 解码产生的像素先由原有快速写入任务落盘，再排队压缩；前台不等待 HC 编码。队列只保存文件名，编码工作区最多一份；输入、编码工作区和验证输出按阶段释放，原生暂存量可在诊断中查看。新文件在完整解压校验通过后原子替换，压缩期间出现更新的源缓存则放弃旧结果。取消、退出或压缩失败时保留有效缓存；无压缩收益的像素记录为格式 2 原始负载，避免反复压缩。

本机现有 55 份纹理缓存已离线转换并逐份验证：1,091,922,348 字节（1041.34 MiB）降至 93,786,778 字节（89.44 MiB），节省约 91.4%，耗时约 51 秒。该转换只运行独立 Mono 文件工具。纹理格式、画质及 Unity 资源驻留预算保持原值。

```powershell
./tests/Run-DiskCacheMonoRegression.ps1
./tools/Compress-TextureCache.ps1
```

第一条在游戏自带 x86 Mono 下执行回归，不启动游戏；本机 81 项通过。第二条可在游戏退出后提前转换指定缓存目录，也可等待插件启动后逐步转换。压缩缓存读取日志为 source=disk-lz4，另记录 textureDecodeMs。完整游戏切换效果由用户测试；调研与原型数据见 TEXTURE_CACHE_COMPRESSION.md。
